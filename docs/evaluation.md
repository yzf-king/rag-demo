# RAG 调参评估实验

> 目的：用固定问题集对比不同切分/检索参数下，RAG 的检索命中质量和回答质量。
> 用法：改 `application.yml` 的 `rag.*` → **清空知识库重新上传** → 依次问 5 个问题 → 记录。

## ⚠️ 每轮实验前必须做（前端评测台已内置整套流程，见 static/index.html ④）

改参数后旧 chunk 还在库里，不清理会污染结果。推荐操作顺序（全部在页面上完成，**不用重启应用**）：
1. 页面「① 检索参数」选预设 A/B/C 或自定义（chunk-size/chunk-overlap 上传时生效，top-k 提问时生效）
2. 点「清空知识库」（等价于下面 SQL）
3. 重新上传语料：基础题 Q1–Q5 用 `sample-knowledge.md`；扩展题 Q6–Q8 用 `sample-knowledge-extended.md`
4. 「④ 评测台」一键逐题提问，每题自动展示引用片段，对照「📌 预期」自评命中与回答质量

命令行等价操作（接口/SQL）：
- 清空：`POST /api/knowledge/clear`，或
  ```bash
  docker exec rag-pg psql -U postgres -d ragdb -c "TRUNCATE knowledge;"
  ```
- 带参数上传：`curl -F file=@sample-knowledge.md -F chunkSize=300 -F chunkOverlap=50 http://localhost:8081/api/knowledge/upload`
- 带 top-k 提问：`curl -X POST http://localhost:8081/api/chat -H "Content-Type: application/json" -d '{"question":"...","topK":3}'`

## 评估问题集（8 问）

> Q1–Q5 针对基础语料 `sample-knowledge.md`（5 节）；Q6–Q8 针对扩展语料 `sample-knowledge-extended.md`（16 节、含数字/语义干扰项）。
> 页面「④ 评测台」已内置本题库，一键即可逐题跑（每题带预期提示 + 引用片段）。

| # | 问题 | 考察点 | 预期 |
|---|---|---|---|
| Q1 | 试用期多久？转正要评估哪些内容？ | 单段内基础检索 | 引用第 1 段 |
| Q2 | 出差回来几天内必须交报销单？住宿每晚上限多少？ | 数字精确性 | 引用报销段 |
| Q3 | 我不想每天去公司坐班，能在家办公吗？ | **语义改写**（问题不含"远程/灵活办公"字样） | 命中办公段 |
| Q4 | 公司裁员会赔几个月工资？ | 资料外 → 必须拒答 | "资料中没有相关信息" |
| Q5 | 两万块的培训费用公司怎么报销？ | 部分覆盖（手册只说 2000 元内规则） | 只答 2000 元内规则，或明确说不含大额规则 |
| Q6 | 公司兴趣小组一年能申请多少钱？ | 数字干扰（500 元经费 vs 500 元住宿） | 每季度上限 500 元（§16），别引成差旅段 |
| Q7 | 试用期能申请远程办公吗？ | 细节考位（§8 末句的限制） | 不能，试用期内不开放 |
| Q8 | 我得了大病能休多久？ | 跨段/长句检索（§5 医疗期） | 医疗期最长 12 个月 |

## 待测配置

| 配置 | chunk-size | chunk-overlap | top-k | 备注 |
|---|---|---|---|---|
| A（基线） | 300 | 50 | 3 | 当前默认 |
| B（小块） | 150 | 30 | 3 | 更细的检索粒度 |
| C（大块大 k） | 600 | 100 | 5 | 上下文更完整，但可能掺无关内容 |

## 结果记录表

### 配置 A：chunk=300 / overlap=50 / k=3（日期：2026-09-12，语料 sample-knowledge.md，入库 11 块）

| 问题 | 引用片段是否命中正确答案所在段落？（看页面 📎 引用） | 回答质量（对/错/幻觉/拒答） |
|---|---|---|
| Q1 | ✓ 命中"试用期与转正"段（另 2 块噪音：标题块、办公段） | ✓ 三个月试用期 + 三项评估内容，全对 |
| Q2 | ✓ 命中"报销与差旅"段（另 2 块噪音） | ✓ 14 天内提交；一线 500 / 其他 350，数字全对 |
| Q3 | ✓ 命中"办公与远程"段（问题无"远程"字样，**语义检索生效**） | ✓ 每周最多 2 天远程，需提前一天申请 |
| Q4 | —（引用全是无关段：年假/试用期/培训，符合预期） | ✓ **拒答"资料中没有相关信息"**，无幻觉 |
| Q5 | ✓ 命中"培训与发展"段（另 2 块为标题块） | ✓ 拒答 + 说明"资料只写了 2000 元内规则，未提两万元规则" |

### 配置 B：chunk=150 / overlap=30 / k=3（日期：2026-09-12，入库 11 块）

**结果与配置 A 逐题完全一致**（引用块与答案均相同）。

原因：`split()` 只在"单个段落长度 > chunk-size"时才切分，而本语料每段都短于 150 字 → 150 / 300 / 600 切出的是**同一批 11 个块**。B 组验证了"参数没生效"，而不是"参数无效"。

### 配置 C：chunk=600 / overlap=100 / k=5（日期：2026-09-12，入库 11 块）

| 问题 | 引用命中 | 回答质量 |
|---|---|---|
| Q1 | ✓ 命中试用期段，但 5 块引用里 4 块是噪音（标题块/办公段/年假段/培训段） | ✓ 全对 |
| Q4 | —（5 块引用全为无关段，比 k=3 时更"乱"） | ✓ **仍拒答**，抗干扰未破 |
| Q5 | ✓ 命中培训段（+标题块、报销段噪音） | ✓ 拒答 + 说明 |

结论：**top-k 从 3 提到 5 没有改善答案质量**，只是每题的噪音块从 2 个涨到 4 个，连带 token 成本上升。

### 扩展语料（配置 A：300/50/3，语料 sample-knowledge-extended.md，入库 34 块）

| 问题 | 引用命中 | 回答质量 |
|---|---|---|
| Q6 兴趣小组经费 | ✓ 命中 §16（**没被 §7 的"500 元住宿"带偏**） | ~ 每季度上限 500 元（对）；并自行推算"×4 = 2000 元/年"——手册未写，属**合理外推**，非幻觉但需留意 |
| Q7 试用期远程办公 | ✓ 命中 §8 末句"试用期内不开放" | ✓ 不能，引用准确 |
| Q8 大病休多久 | ✓ 命中 §5 医疗期 | ✓ 最长 12 个月 |
| Q4 裁员赔偿（对照） | —（噪音） | ✓ **仍拒答**——尽管 §13 离职流程是语义近邻 |

## 判定标准

- **检索命中**：Q1-Q3 引用里包含正确答案所在段落 = 命中；引用和问题无关 = 漏检
- **回答**：依据命中段落答对 = 好；没答对但引用对 = 检索好生成差（可能是 prompt 问题）；引用不对答案却对 = 存疑，重点查
- **拒答**：Q4 答出"资料中没有相关信息" = ✅ 满分；Q4 编了答案 = ❌ 严重幻觉

## 结论区（2026-09-12 实验后填写）

**1. 三组配置的回答质量没有差异——真正的变量不是参数，是切分策略。**
本切分器只在"段落超长"时才切，示例语料每段都短于最小的 chunk-size（150），所以 A/B/C 切出的是同一批 11 块。这是本次实验最有价值的发现：**调参前要先验证参数是否真的在生效**，否则三组对比表是"同一份数据填三遍"，结论必然伪相似。要真正验证 chunk-size，需要一份"单段超长"的语料（比如把 16 节拼成一整段的长文档）。

**2. 发现了切分器的真实缺陷：标题块污染。**
`## 标题` 被空行切成独立小块，语义弱但偶尔相似度不低，稳定占掉 top-k 里 1–2 个名额（Q1/Q2/Q3/Q5 都出现）。改进方向：标题与后文合并成一块、或过滤过短块（< 40 字）。

**3. top-k 3→5 是负优化**：答案一样，噪音翻倍，成本上升。本语料规模下 k=3 已足够；k 该由"语料密度 + 块大小"决定，不是越大越好。

**4. 拒答能力稳定、可信**：Q4 在两版语料上、在 k=3 与 k=5 下都正确拒答；Q5 部分覆盖时给出"资料只写了 X，未提 Y"的诚实回答。system prompt 里"资料中没有相关信息，不要编造"的约束被验证有效。

**5. 语义检索有效**：Q3 问题里不含"远程/办公"字样仍命中办公段——这是 RAG 相对关键词检索的核心价值，也是 embedding 存在意义的直接证据。

**6. 扩展语料印证了干扰项设计有效**：500 元住宿 / 500 元团建、四处"评估"、§13 离职流程等近义干扰项都没有把检索或回答带偏，说明当前配置在"同主题近义干扰"下表现稳健。

**面试怎么讲（三个故事）**
- ① "我做的第一轮参数实验结论是**参数没生效**"——先验证自变量真的在变，再谈对比；讲这个能体现实验设计意识。
- ② "评估集我用四种题型设计：单段检索、数字精确、语义改写、库外拒答"——库外拒答是幻觉底线，必须单列。
- ③ "每轮实验前 TRUNCATE 知识库"——不做数据隔离，新旧 chunk 混检，结论全废（我实测过一次污染：两种语料同时在库，结果无法判定）。

**后续改进（未做，可作下一轮）**：切分器升级（标题合并 + 最小块长过滤 + 句子级切分）→ 加相似度阈值（低于阈值直接拒答）→ 引入 rerank（bge-reranker）。
